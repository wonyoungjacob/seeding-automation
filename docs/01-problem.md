# 1. 문제 정의 — 시딩에서 손이 가는 곳

## 과제에서 주어진 조건

- 블로거·인플루언서에게 제품을 보내고 후기를 받는 시딩을 꾸준히 운영 중
- 대상 찾기부터 연락, 게시 여부 확인까지 손으로 하는 일이 많음
- 플랫폼 이용약관을 지키는 범위에서, 자동화가 어려운 부분을 어떻게 다룰지도 포함

| 플랫폼 | API | 연락 자동화 |
|---|---|---|
| 네이버, 유튜브 | 있음 | 메일 자동 전송 가능 |
| 인스타그램 | 있음 | DM 자동 전송 불가 |
| 샤오홍슈 | 공개 API 없음 | — |

이 문서는 인스타그램을 먼저 다룹니다.

## 시딩 한 건이 지나가는 단계

| 단계 | 하는 일 | 인스타그램에서 손이 가는 이유 |
|---|---|---|
| ① 발굴 | 후보 계정 찾기 | 검색·탐색 탭을 사람이 훑어야 함 |
| ② 선별 | 팔로워, 반응, 브랜드와 결이 맞는지 확인 | 계정마다 들어가 숫자를 눈으로 보고 시트에 옮김 |
| ③ 첫 연락 | 제안 메시지 보내기 | DM을 자동으로 보낼 수 없어 한 명씩 작성하고 전송 |
| ④ 회신 관리 | 답장 확인, 조건과 주소 조율 | DM함을 수시로 열어 보고 시트 상태를 손으로 갱신 |
| ⑤ 발송 | 제품 배송 | (이 제안의 범위 밖) |
| ⑥ 게시 확인 | 올렸는지, 반응이 어땠는지 확인 | 계정마다 다시 들어가서 확인 |

"손이 가는 이유"는 과제 설명과 면접에서 들은 내용을 바탕으로 한 추정입니다. 실제와 다른 부분은 알려 주시면 바로 반영하겠습니다.

## 문제를 단계별로 다시 보면

"DM 자동 전송 불가" 때문에 인스타그램 전체가 수동으로 남아 있는 것처럼 보입니다. 하지만 단계별로 나눠서 공식 문서를 확인해 보면, 정책상 사람이 꼭 해야 하는 일은 생각보다 좁습니다.

| 단계 | 공식 API로 자동화할 수 있는가 |
|---|---|
| ① 발굴 | **일부 가능.** 이미 우리 계정을 태그하거나 댓글을 단 계정, 담당자가 모아 둔 계정에서 출발해 넓힐 수 있음. 처음 보는 계정을 조건으로 검색하는 것은 Meta 검수를 통과해야 열림 |
| ② 선별 | **가능.** 계정명만 있으면 팔로워, 게시물, 반응 수치를 자동으로 가져와 점수를 매길 수 있음 |
| ③ 첫 연락 | **전송만 불가.** 누구에게 보낼지 정렬하고, 문안을 만들고, DM 창을 여는 것까지는 가능 |
| ④ 회신 관리 | **가능(검증 필요).** 받은 DM을 읽어 시트 상태를 갱신할 수 있음 |
| ⑥ 게시 확인 | **가능.** 우리를 태그한 게시물, 시딩한 계정의 새 게시물을 자동으로 확인할 수 있음 |

근거와 조건은 [2. 인스타그램에서 되는 것과 안 되는 것](02-instagram-api.md)에 정리했습니다.

## 목표

> **사람은 "누구에게 보낼지 승인"과 "DM 전송"만 한다. 그 앞뒤는 도구가 한다.**

구체적으로는 다음 상태를 만드는 것입니다.

- **후보 한 명을 시트에 정리할 때**: 사람이 하는 일은 계정명을 적는 것 한 번. 숫자와 점수는 자동으로 채워짐
- **DM 한 건을 보낼 때**: 사람이 하는 일은 복사, 붙여넣기, 전송. 대상을 고르거나 문안을 쓰는 시간은 없음
- **회신과 게시를 확인할 때**: 시트를 열면 이미 갱신되어 있음. 계정을 하나씩 다시 방문하지 않음

기존에 쓰고 계신 시트와 파이썬 스크립트 흐름을 바꾸지 않고, 막혀 있던 구간에 끼워 넣는 형태로 만듭니다.

## 확인하고 싶은 것

아래 세 가지를 알면 제안을 실제 운영에 더 정확히 맞출 수 있습니다.

1. 회사 인스타그램 계정이 프로페셔널(비즈니스 또는 크리에이터) 계정이고 페이스북 페이지와 연결되어 있는지. 공식 API를 쓰기 위한 전제 조건입니다.
2. 한 달에 연락하는 계정 수와 지금 쓰는 선별 기준(팔로워 범위 등).
3. 현재 시딩 관리 시트의 열 구성. 기존 시트에 그대로 붙도록 출력 형식을 맞추기 위해서입니다.
